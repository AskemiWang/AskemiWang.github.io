Data Representation

Created2026-11-14|Updated2026-11-19|Tech
|Post Views:

Introduction

Computers represent data using bits, commonly written as 0 and 1. By organizing and interpreting these bits according to agreed rules, we can represent text, images, video, and audio.

This article follows those rules from basic values to complete representations, beginning with images.

1. RGB and Color Representation

1.1 Light and Human Color Vision

Light possesses various spectral compositions. Upon entering the eye, light stimulates photoreceptor cells, and the visual system generates the perception of color based on these stimuli.

In humans with normal color vision, photopic (daylight) vision relies primarily on three types of cone cells, each with a distinct response to different ranges of light wavelengths. Under specified viewing conditions, the stimulation of these three types of cells by a given light source can be characterized by three quantities.

This implies that two light sources with different spectral compositions can still be perceived as the same color, provided they elicit the same responses in the three cone types under the same viewing conditions.

This principle provides a basis for display devices to reproduce a wide range of colors using a limited number of light sources.

1.2 RGB and Color Gamut

By selecting red, green, and blue as primary lights and independently controlling their intensities, display devices can generate a range of color perceptions.

For instance, an appropriate mixture of red and green light is perceived as yellow.

A color reproducible using this set of primary lights can be described by three components:

  • Red Component
  • Green Component
  • Blue Component

The range of colors that a device can reproduce is its Color Gamut. A fixed set of three real primary lights cannot reproduce every color visible to the human eye through non-negative mixtures.

1.3 Channels and Bit Depth

The R, G, and B components are stored as three Channels. To store their values using finite space, we choose a Bit Depth for each Channel.

3.4 RGBA8 and Alpha

RGB describes a Pixel’s color. When placing an image over a background, we may also need to describe how opaque each Pixel is. RGBA adds an Alpha Channel for that purpose.

For example, a red icon on a blue background may have fully opaque, partially transparent, and fully transparent areas.

In RGBA8, each of the four Channels uses 8 bits:

Alpha Value Meaning
255 Completely Opaque
128 Approximately 50% Opaque
0 Completely Transparent

Placed on an opaque blue background:

  • Alpha 255: the foreground red completely covers the background.
  • Alpha 128: both foreground red and background blue affect the final color.
  • Alpha 0: the foreground contributes no color, so the background blue is visible.

These examples describe the RGB color separately from Alpha. Alpha expresses opacity; it is not another color component.

3.5 Gray8

Pixel Formats depend on the information we need to represent. RGB describes color, and RGBA adds opacity. If we only need black-to-white levels, a single Channel can describe each Pixel.

In common RGB representations, equal R, G, and B values produce black, white, or a neutral gray:

RGB Value Appearance
(0, 0, 0) Black
(64, 64, 64) Darker Gray
(128, 128, 128) Gray
(192, 192, 192) Lighter Gray
(255, 255, 255) White

For such a black-to-white representation, we can store one Gray Value per Pixel instead of three color components.

In Gray8, the Channel uses 8 bits, so each Pixel occupies 1 byte:

Intermediate values indicate different gray levels. These are encoded values; they are not necessarily proportional to physical light output.

Representation Data Size
Original RGB8 24 bytes
Original RGB8 + RLE 32 bytes
Quantized RGB8 24 bytes
Quantized RGB8 + RLE 4 bytes

The smaller result comes from Quantization + RLE. Quantization changes the values; RLE then represents the repeated result compactly.

A decoded value of 248 no longer identifies which original value produced it. Information has been lost, making this a teaching example of Lossy Compression.

Lossy Compression does not guarantee that the changes are invisible. Whether the loss is acceptable depends on the image and its intended use.

4.4 Encoded Size and Quality

The previous example reduces Encoded Size while keeping the same number of Pixels. Several different properties must therefore be distinguished:

Property Meaning
Pixel Dimensions Width and Height in pixels
Raw Data Size Bytes used by the chosen raw Pixel Format and layout
Encoded Data Size Bytes used by the encoded representation
Quality Fidelity to the original content and the resulting visual appearance

For the eight-Pixel example from Section 4.3:

Representation Pixel Dimensions Data Size Exact Recovery
Raw RGB8 8 * 1 24 bytes Yes
RLE 8 * 1 32 bytes Yes
Quantization + RLE 8 * 1 4 bytes No

The RLE representation is larger than Raw RGB8 but recovers exactly the same content. More bytes do not necessarily mean higher Quality.

The Quantization + RLE representation keeps the same Width and Height but changes Pixel Values. Equal Pixel Dimensions do not guarantee equal Quality.

When the 4-byte representation is decoded into tightly packed RGB8, it again requires 8 * 3 = 24 bytes to hold the eight decoded Pixels. Encoded Data Size and decoded Raw Data Size describe different representations.

The comparisons above count the data representation itself. Image files also need a defined way to organize their information, which is the next topic.
